# Repo — FelipeBrenes-Portfolio (vanilla site)

Static portfolio: plain HTML + CSS + vanilla JS. **No package.json, no build, no tests, no lint, no CI.** There is nothing to install or compile.

## Commands

- Serve locally: `python -m http.server 5173` — then open `http://localhost:5173`. There are no npm scripts.

## Content model

- The page is **data-driven and bilingual (ES/EN)**. All content lives in the `content` object at the top of `src/scripts/main.js`, with two keys — `content.es` and `content.en` — each holding `strings` (static copy), `technologies`, `experience`, `projects`, `education`. To change content, edit **both** language blocks. Site default language is Spanish.
- Static HTML copy gets translated via `data-i18n="<key>"` attributes on elements; `setLanguage(lang)` in `main.js` swaps text from `content.<lang>.strings` and re-renders the dynamic sections. The `<button id="lang-toggle">` (fixed top-right, styled like the other buttons) toggles between ES and EN and shows the language you switch to ("EN"/"ES").
- The `<section>` bodies in `index.html` are empty containers (`#technologies`, `#experience`, `#projects`, `#education`) filled by `mount()` on load from the active language. To change content, edit `content.es`/`content.en` — **not** the HTML.
- Each project in `projects` may carry an `icon` name (renders `assets/icons/<name>.svg` in its preview) and a `repoUrl`/`demoUrl` for the link buttons.
- **Site language is Spanish** — write any new copy in Spanish, matching existing content.
- Contact links live in `index.html`, not in `portfolioData`. The email is plain copyable text inside `.email-block` with a `.email-copy` button whose `data-copy` attribute holds the address (wired up by `initEmailCopy()` in `main.js`, which runs after `mount()`). GitHub/LinkedIn are `<a class="icon-link" href="..." target="_blank">`. `mail`/`github`/`linkedin`/`copy` in `main.js` are icon-names in the `icons` map, nothing else.

- The page has a fixed starfield background: `<div class="container">` wrapping `.space-1/2/3` layers in `index.html`, styled in `main.css` under "Star Animations" (`.container` is `position: fixed; inset: 0; z-index: 0`, `main` is `position: relative; z-index: 1` so content paints on top), and generated by `generateSpaceLayer()` in `main.js`.
- Layout: `.portfolio` is up to 1000px wide. `.hero` (personal info) and `.footer` are centered (`text-align: center`, `.social-links` centered). All `.section`s from "Sobre mí" down use a 2-column grid (`grid-template-columns: minmax(180px, 230px) 1fr`) with the `<h2>` title on the left and content on the right; collapses to 1 column at ≤460px.
## Styling

- Design tokens are CSS custom properties under `:root` in `src/styles/main.css` (`--bg`, `--border`, `--text`, `--teal`, `--teal-dark`, `--teal-soft`, ...). Accent/UI colors use a teal-turquoise palette — reuse the tokens and add new colors as tokens — do not hardcode hex values.
- Responsive breakpoints: `@media (max-width: 760px)` and `@media (max-width: 460px)`.

## Icons

- Tech logos and project artwork live as SVG files in `assets/icons/` (added by the user, some as "dark" variants with their own baked-in background). The `techIcons` map in `src/scripts/main.js` maps each technology name to a file there; `createTechnology()` renders an icon-only `<img class="tag__icon" src="./assets/icons/<name>.svg">` with no label text (falls back to the `code` glyph if unmapped).
- Small UI glyphs (`mail`, `file-text`, `github`, `linkedin`, `map-pin`, `code`, `link`, `copy`) are inline SVGs injected at runtime: a `<span data-icon="name">` is replaced by `renderIcons()` using the `icons` map in `src/scripts/main.js`. The name must be a key in that map, otherwise the span renders empty.

## CV

- The CV download button (`<a class="icon-link" href="./assets/Felipe_Brenes_CV.pdf" download>`) points at the binary PDF in `assets/` — overwrite that file to update the downloadable CV. Keep the filename.
- `assets/cv.html` is a standalone temporary page (no JS, no shared styles). Edit it directly; it does not use `portfolioData` or `main.css`. Currently not linked from the site.

# context-mode — MANDATORY routing rules

context-mode MCP tools available. Rules protect context window from flooding. One unrouted command dumps 56 KB into context.

## Think in Code — MANDATORY

Analyze/count/filter/compare/search/parse/transform data: **write code** via `context-mode_ctx_execute(language, code)`, `console.log()` only the answer. Do NOT read raw data into context. PROGRAM the analysis, not COMPUTE it. Pure JavaScript — Node.js built-ins only (`fs`, `path`, `child_process`). `try/catch`, handle `null`/`undefined`. One script replaces ten tool calls.

## BLOCKED — do NOT attempt

### curl / wget — BLOCKED
Shell `curl`/`wget` intercepted and blocked. Do NOT retry.
Use: `context-mode_ctx_fetch_and_index(url, source)` or `context-mode_ctx_execute(language: "javascript", code: "const r = await fetch(...)")`

### Inline HTTP — BLOCKED
`fetch('http`, `requests.get(`, `requests.post(`, `http.get(`, `http.request(` — intercepted. Do NOT retry.
Use: `context-mode_ctx_execute(language, code)` — only stdout enters context

### Direct web fetching — BLOCKED
Use: `context-mode_ctx_fetch_and_index(url, source)` then `context-mode_ctx_search(queries)`

## REDIRECTED — use sandbox

### Shell (>20 lines output)
Shell ONLY for: `git`, `mkdir`, `rm`, `mv`, `cd`, `ls`, `npm install`, `pip install`.
Otherwise: `context-mode_ctx_batch_execute(commands, queries)` or `context-mode_ctx_execute(language: "javascript", code: "...")`. Use `language: "shell"` only when code matches the host shell.

### File reading (for analysis)
Reading to **edit** → reading correct. Reading to **analyze/explore/summarize** → `context-mode_ctx_execute_file(path, language, code)`.

### grep / search (large results)
Use `context-mode_ctx_execute(language: "javascript", code: "...")` in sandbox for portable filtering/counting.

## Tool selection

0. **MEMORY**: `context-mode_ctx_search(sort: "timeline")` — after resume, check prior context before asking user.
1. **GATHER**: `context-mode_ctx_batch_execute(commands, queries)` — runs all commands, auto-indexes, returns search. ONE call replaces 30+. Each command: `{label: "header", command: "..."}`.
2. **FOLLOW-UP**: `context-mode_ctx_search(queries: ["q1", "q2", ...])` — all questions as array, ONE call (default relevance mode).
3. **PROCESSING**: `context-mode_ctx_execute(language, code)` | `context-mode_ctx_execute_file(path, language, code)` — sandbox, only stdout enters context.
4. **WEB**: `context-mode_ctx_fetch_and_index(url, source)` then `context-mode_ctx_search(queries)` — raw HTML never enters context.
5. **INDEX**: `context-mode_ctx_index(content, source)` — store in FTS5 for later search.

## Parallel I/O batches

For multi-URL fetches or multi-API calls, **always** include `concurrency: N` (1-8):

- `context-mode_ctx_batch_execute(commands: [3+ network commands], concurrency: 5)` — gh, curl, dig, docker inspect, multi-region cloud queries
- `context-mode_ctx_fetch_and_index(requests: [{url, source}, ...], concurrency: 5)` — multi-URL batch fetch

**Use concurrency 4-8** for I/O-bound work (network calls, API queries). **Keep concurrency 1** for CPU-bound (npm test, build, lint) or commands sharing state (ports, lock files, same-repo writes).

GitHub API rate-limit: cap at 4 for `gh` calls.

## Output

Write artifacts to FILES — never inline. Return: file path + 1-line description.
Descriptive source labels for `search(source: "label")`.

## Session Continuity

Skills, roles, and decisions persist for the entire session. Do not abandon them as the conversation grows.

## Memory

Session history is persistent and searchable. On resume, search BEFORE asking the user:

| Need | Command |
|------|---------|
| What did we decide? | `context-mode_ctx_search(queries: ["decision"], source: "decision", sort: "timeline")` |
| What constraints exist? | `context-mode_ctx_search(queries: ["constraint"], source: "constraint")` |

DO NOT ask "what were we working on?" — SEARCH FIRST.
If search returns 0 results, proceed as a fresh session.

## ctx commands

| Command | Action |
|---------|--------|
| `ctx stats` | Call `stats` MCP tool, display full output verbatim |
| `ctx doctor` | Call `doctor` MCP tool, run returned shell command, display as checklist |
| `ctx upgrade` | Call `upgrade` MCP tool, run returned shell command, display as checklist |
| `ctx purge` | Call `purge` MCP tool with confirm: true. Warns before wiping knowledge base. |

After /clear or /compact: knowledge base and session stats preserved. Use `ctx purge` to start fresh.
